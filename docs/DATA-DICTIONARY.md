# 格口交接账字段定义

| 字段 | 类型 | 定义 |
|---|---|---|
| 保管单 | 字符串 | 保留前导零，旧名为业务编号 |
| 修订号 | 整数 | 正整数，兼容版本列。最高修订的业务值一致时保留首次原始行 |
| 提交时间 | RFC 3339 时间 | 必须含偏移量，统一为 UTC，版本裁决以修订号为准 |
| 格口事件 | 业务文本 | 必填，按业务段解析 |
| 结算截止分钟 | 业务文本 | 必填，按业务段解析 |
| 原始备注 | 字符串 | 可空，可内含换行 |
| 现场来源 | 字符串 | 门磁口径 2.0 必填。门体现场的采集来源，不接受空值、空值哨兵或 `无` |
| 事件原因 | 字符串 | 门磁口径 2.0 必填。该门事件的现场原因，不接受空值、空值哨兵或 `无` |
| 外部记录值(占用分钟) | 十进制数 | 参照值。真实零值与找不到键分别表示 |

事件格式为 分钟:动作:事件号，支持存件 IN、开门 OPEN、关门 CLOSE 与取件 PICK。占用未闭合时累至结算截止。

空字符串、`N/A`、`-`、`NULL`、`未知` 均拦在必填字段。`无` 可以表示空集合，按具体业务字段解释。
逐行记录保留物理起始行号。JSON 的计量值为十进制字符串。

## 字段口径

| 口径 | 必需字段 | 适用 |
|---|---|---|
| 1.0 | 保管单、修订号、提交时间、格口事件、结算截止分钟 | 旧班次兼容；来源无现场来源与事件原因两列 |
| 2.0 | 1.0 全部，另加现场来源、事件原因 | 新班次；两列须同时出现 |

口径按来源表头识别，不按行内默认值猜测：

- 两列都不存在 → 按 1.0 复算，可作为旧班次重算与独立账核对。
- 两列都存在 → 按 2.0 复算。任一行现场来源或事件原因缺失（含空值哨兵与 `无`），该行隔离为 `SOURCE_MISSING` / `REASON_MISSING`，不填默认值，不进正式差异。
- 只有其中一列 → 直接报 `CALIBER`，批次不受理。
- 显式指定口径与表头不一致 → 报 `CALIBER`（409）。切换失败时保留并打开同输入的旧版正式结论，不写入新批次。

隔离发生在版本裁决之后：最高修订若缺现场证据，整条键隔离，较低修订不会被提升顶替。
独立对账将隔离键标为 `ISOLATED`，并同时从两侧合计中剔除，因此外部账差额与交付结论共用同一口径。

## 流水线记录

运行清单保存来源和外部账的 SHA-256、规则版本、口径、耗时、计算参数和创建时刻。
批次指纹包含口径，同一输入换口径复算会形成新批次。
影子版本与重复行保留原始字段。复核按版本追加，旧版本提交返回 409。

导入原文件时指纹取源字节，编辑预览后以提交的 UTF-8 文本计算。
